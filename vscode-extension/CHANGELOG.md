# Changelog（第一部分：VSCode 扩展）

版本号规则与 CLI 一致：MINOR 为功能/模块更新，PATCH 为测试或实际运行中发现的缺陷修正。

## [0.1.2] — 修正独立审查发现的 5 个缺陷（均为低严重度、需罕见输入）

在用户要求"仔细核对"后，安排了一次独立审查：不改动项目文件，对解析器做 30 万个输入的差分模糊测试（与 `sax` 严格模式对比）、大文件与深嵌套性能测试、位置边界测试。没有发现崩溃、层级错误或定位错误；以下缺陷均先写成失败的回归测试（`test/regression/ReviewDefects.test.ts`，修复前 10 个用例失败），再修正。详细原因见 GUIDE.md 第 8 节。

### Fixed
- **BUG-V2** `<!-->…-->` 形式的注释被提前结束，注释中的元素出现在大纲里。
- **BUG-V3** DOCTYPE 内部子集里的注释/处理指令含引号或 `[` 时，格式良好的文件大纲为空。
- **BUG-V4** 嵌套数千层以上的合法文件，构建符号树时栈溢出导致大纲为空（改为非递归）。
- **BUG-V5** `id` 中的字面换行、制表符未按 XML 规则规范化为空格。
- **BUG-V6** `ICON.SVG` 等大写扩展名有 `[]` 标记却没有大纲（文档选择器改为不区分大小写）。

### Added
- `README.md`：真实运行证据表，把用户在 macOS 上的截图与 A.1/A.2 各项要求逐条对应；说明 `.vsix` 是构建产物。

## [0.1.1] — 修正：点击大纲节点会切换到图片预览

### Fixed
- **BUG-V1**（用户在 macOS 的 VSCode 中实际运行时发现）用文本编辑器打开 `.svg` 后，点击大纲节点会立即切换成图片预览，无法定位源码。
  - 原因：该环境中 `.svg` 的默认编辑器是图片预览；点击大纲节点时 VSCode 按默认编辑器重新打开文件再定位。
  - 验证：用户手动添加 `"workbench.editorAssociations": {"*.svg": "default"}` 后，点击节点光标正确定位，确认了原因。
  - 修正：扩展通过 `contributes.configurationDefaults` 提供该默认值（GUIDE E11），用户设置仍然优先。
  - 测试：`test/extension/Manifest.test.ts` 检查清单中的该默认值。
