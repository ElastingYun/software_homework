# 第一部分（VSCode 插件实践）过程记录

第 1–7 节保留原开发者与 Claude Code 协作时的第一人称记录。文末的集成复核由后续审查者完成。[版本变更](CHANGELOG.md) · [开发记录](GUIDE.md)

### 1. 先弄清楚任务，再观察现有行为

小组分工后我负责第一部分。动手前我先问了 AI 两个问题：Phase 1 和 Phase 2 的联系是什么，以及"观察现有大纲"到底是什么意思。AI 解释后，我在自己电脑上用 VSCode 打开 Phase 1 生成的 `demo.svg`，观察到三点：

- 双击 `.svg` 默认以图片预览打开；
- 改用文本编辑器打开后，语言模式是 XML；
- 大纲面板显示"在文档'demo.svg'中找不到符号"。

截图见 `docs/images/before-*.png`。这三条观察被写进 `GUIDE.md` 第 2 节，直接决定了设计。例如因为第二点，大纲只对 `*.svg` 注册，而不是对所有 XML 注册。

### 2. AI 的实现方案与安装方式

AI 先写了指导文档 `GUIDE.md`，再实现代码和测试（`[]` 文件标记、带位置记录的容错解析器、大纲提供者）。我的电脑一开始没有 Node.js，AI 因此把扩展打包成 `.vsix`，我在 VSCode 里"从 VSIX 安装"即可，不需要从源码构建。

### 3. 我在实际运行中发现 bug，让 AI 修正（BUG-V1，v0.1.1）

装好 v0.1.0 后，我发现：大纲能显示，但**点击其中的节点（如 `rect#bg`）会立即切换回图片预览**，无法定位源码。这违反了 A.2"点击节点定位到相应源代码"。

- AI 推测原因是：`.svg` 的默认编辑器是图片预览，点击大纲时 VSCode 会按默认编辑器重新打开文件。它让我先手动加一条设置来验证这个推测。
- 我在设置界面里加了 `workbench.editorAssociations: {"*.svg": "default"}`，点击后光标确实停在源码对应行，推测得到证实。
- 我让 AI 修正。它把这条默认设置放进扩展清单（`contributes.configurationDefaults`），装上即生效，用户设置仍然优先；同时补了测试，并在文档中说明了这个修正带来的副作用：双击 `.svg` 默认以文本方式打开。

### 4. 我核对需求，补齐真实运行证据

我问 AI"现在已经满足部分一的要求了么"。AI 逐条比对后说明：单元测试覆盖了四种必测情况，但需求 §7 还要求真实运行的证据，其中"无 id 元素""编辑更新""不完整 XML"三项还没有截图。我随后在 VSCode 里补拍了这几张：

- 嵌套容器的点击定位；
- 把 `id` 删空后大纲立即从 `text#title` 变成 `text`（同时证明了编辑更新和无 id 显示）；
- 删掉 `</g>` 后大纲清空、没有报错。

五张实现后的截图与需求的对应关系见验收记录。[界面演示](DELIVERY.md)

### 5. 检查 AI 自己的结论：xmldom 到底能不能给出位置

AI 在指导文档初稿里写"Phase 1 使用的 xmldom 不提供完整位置信息"，以此说明为什么不复用 Phase 1 的解析代码。写 A.3 复用分析时，它没有沿用这个说法，而是写了验证脚本实际运行（`docs/evidence/xmldom-probe.mjs`）。结果修正了一处：xmldom 其实**会记录开始标签的行列**，只是不记录结束位置。指导文档和分析中的相应说法都已更正。

### 6. 我要求"仔细核对、并行执行"：独立审查与修正（BUG-V2～V6，v0.1.2）

我要求 AI 仔细核对第一部分还差什么，并且能并行的工作就并行做。AI 一边写 A.3 分析，一边安排了一个独立审查：不改动项目文件，对解析器做 30 万个输入的差分模糊测试（与 `sax` 严格模式对比），另外测试大文件、深嵌套和位置边界。

- 独立审查提出了 5 项修正，包括以 `>` 开头的注释被提前结束、2 万层嵌套时大纲为空、大写的 `ICON.SVG` 有标记却没有大纲。
- 每个缺陷都**先写成回归测试并确认失败**（修复前 10 个用例失败），再修正，然后发布 v0.1.2。
- 审查报告中也有不准确的地方：它看的是一份过时的副本，因而误报"v0.1.1 的修正没有提交"。AI 核对了 git 记录后确认已经提交，没有照单全收。

### 7. 过程中 AI 的失误

- 有一次在网络盘上分步提交，第二个提交没有执行成功，只提交了测试、没提交修正本身。AI 查看 git 记录时发现，随后补交。
- 写完 README 后重新打包时，打包工具因为 README 里的相对链接报错；新加的测试里有一处写法不符合工程的模块格式，类型检查报错。这两处都是在发布前的检查中发现并修正的。

### 原开发者小结

- 我在第一部分做的事主要是：观察现有行为并截图、在真机上安装运行并发现 BUG-V1、核对需求并补齐运行证据、要求 AI 仔细核对。
- 有些问题只有在真实环境里运行才能发现，比如 BUG-V1 只在"默认用图片预览打开 svg"的环境里出现，单元测试测不到。AI 的结论也需要检查，比如它对 xmldom 的判断就是实际验证后才修正的。

## 2026 年 11 月 26 日 · 主仓集成复核

小组指定使用 `ElastingYun/software_homework`。集成时以该仓库的 `final`（`8edfba0`）为基线，按顺序接入开发者关于预研、实现、回归测试、修复和截图的提交。A.3 的复用分析据此核对该仓库中的 `SvgReader`、图形模型和 `TreeRenderer`。[A.3 分析](ANALYSIS.md)

复核者检查了交接稿里两个仍待独立验证的判断。首先，在 macOS 上以 VS Code 1.147.0 干净配置加载交接 VSIX 的扩展内容，确认扩展自动激活，且清单提供的编辑器默认关联已生效。通过原生 Outline 选择 `rect#start` 后，活动文本编辑器光标位于 `flowchart.svg` 第 5 行。其次，把嵌套示例复制为 `UPPER.SVG`，通过真实宿主请求符号，得到 `g#diagram` 和 `g#nodeB` 等节点。同次复核还验证了未保存编辑、不完整 XML 和补全后的恢复。[宿主观测记录](docs/evidence/vscode-host.json)

对照 0.1.2 的源码，复核者发现早期分析仍描述小写文件选择器与递归转换。现版用 `**/*.[sS][vV][gG]` 匹配扩展名，`toSymbols()` 通过显式栈构建符号树，`toSymbol()` 转换单个节点。集成交付同步更新了这些说明，并将 A.3 的说明与演示接入仓库报告。在 Node.js 24.3.0 下完成类型检查、79 个用例和 VSIX 打包。[验收记录](DELIVERY.md) · [小组报告](../doc/README.md)
